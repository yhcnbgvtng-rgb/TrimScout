# bigJson.js: parse each element as it is read (2026-11-07) — code only until Paul's GO

## What and why
`readJsonStreaming` (used for every file above 64 MB) collected the text of every top-level element, then parsed them. The load therefore held a second, file-sized copy of the
data next to the parsed objects. 600 MB synthetic dom_index.json, merge-mode load: peak heap 1206 MB / RSS 1354 MB before, 658 MB / 790 MB after. No single string was ever
file-sized, before or after; this is heap, not the V8 string limit. Results, error types (SyntaxError, ENOENT) and duplicate-key behaviour (last wins) are unchanged.

## Consumers of readJsonLarge (all get the new reader)
dom_store.js (dom_index.json), standalone.js (brand shard, daily changes), enricher.js, vinCacheShared.js, inventory_shards.js, legacyShardSplit.js. The repo suite covers them
(`npm test` in scrapers/lightsail-crawler) plus the 600 MB scripts below. scripts/box/inventory-sync.mjs has its own reader and is unaffected.

## Run it (nothing is staged on the box)
```
ssh box1 'bash -s -- check'   < install.sh   # read-only trial on copies in a mktemp dir
ssh box1 'bash -s -- apply'   < install.sh   # ONLY on Paul's GO, 07:00-21:30 ET, nothing running. Same for box5. Backup: ~/backups/bigjson-parse-20261107
ssh box1 'bash -s -- restore' < install.sh
```
`install.sh` is generated by `python3 build-install.py` (repo root) from `install.template.sh`; `test/bigjson_parse_package.test.js` fails if they drift.

## Compatibility change (read this)
- The 2026-11-06 packages (`dom-index-save-boxes-15`, `dom-index-delta-boxes-15`) pin the OLD bigJson.js (650637d9). Their pins and install.sh files are NOT edited: they record what was installed then.
  Their tests now compare against a frozen copy, `test/fixtures/bigJson.2026-11-06.js`, instead of the current `src/bigJson.js`.
- After this package is applied, those two packages' `apply`/`check` REFUSE ("bigJson.js md5 is not the pinned…") on that box. That is intended: they are already installed on box1/box5.
  Their `restore` modes do not check bigJson.js and still work. Use this package's `restore` to put the old bigJson.js back.
- box2/box3/box4 are not covered (not installed there; #720/#721 are not on them).

## Not changed / not claimed

Partial-store miss-counter verification is still open and is not part of this package.
